## 摘要

这是一条面向初学者的学习路径建议帖，主张按项目学而不是按清单学。作者给出的顺序是：先掌握 Python、HTTP、Git 并会写调用 API 的脚本；第一个项目做笔记问答机器人，在过程中自然会遇到切块、向量检索、提示词问题；第二步建立 30 个自己真会问的问题作为评测集，每次改动都跑；能诊断错误来源（检索问题还是模型理解问题）之后，再去学 Agent 和微调。作者自称按此顺序走了三个月，认为评测环节收获最大。

## 核心观点

- 按项目学优于按清单学：切块、向量检索、提示词只有在真实问答项目里才会成为必须解决的问题。
- 评测的门槛可以很低：30 个自己真会问的问题就构成一套可用回归集，关键是每次改动都跑一遍做对比。
- 诊断能力是进阶前提：要能区分错误来自检索没召回还是模型理解错误，否则调 Agent、微调都是盲调。
- 学习顺序应由依赖关系决定：先把 RAG 和评测跑通，再学 Agent 和微调这类更复杂的手段。

## 实践方法

1. 打基础：熟练 Python、HTTP、Git，能写一个调用 API 的小脚本。
2. 第一个项目：给个人笔记做问答机器人，实践切块、向量检索、提示词设计。
3. 整理 30 个自己真的会问的问题，作为固定评测集，每次改动后全部重跑并对比结果。
4. 针对失败案例判断归因：检索没找到，还是模型理解错了。
5. 能清晰解释错误原因后，再进入 Agent、微调等方向。
